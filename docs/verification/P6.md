## Matched continuation interfaces

`nnwa train --multirun training=continued_full,fixed_window,dynamic_window`
checks each three-arm replicate for matching parent, physical and data settings,
optimizer and scheduler choices, execution settings, and update budgets. Each
arm copies the full terminal base model state and starts a new optimizer and
scheduler. The shared architecture retains the learned empty embedding, query
projection, scalar head, width 256, and four GRU layers. Continuation starts at
phase update zero and retains the parent counter. At terminal phase update
$U_1$, the checkpoint records cumulative update $U_0+U_1$, $U_1B$ trajectories,
and $2U_1B$ query examples. [PyTorch optimizer state](https://docs.pytorch.org/docs/2.7/optim.html)

Every trajectory supplies a full-context global query and one uniformly sampled
core query. The mean global and sampled-core BCE terms each receive weight
$1/2$. S+ uses full core context, W uses fixed deployment windows, and D uses
dynamic windows. D maps two independent uniform integer draws to
$\{0,\lceil d/2\rceil,d\}$, giving nine equiprobable ordered pairs. One pair is
used per effective minibatch and reused in every accumulation microbatch.
The draw uses its own PCG64 stream. The core label table and the physical
availability rule are shared across arms. This is a study-specific window
policy inspired by dynamic chunk training. [Li et al.](https://arxiv.org/abs/2304.09325)

Continuation audit schema 1 is stored in the checkpoint and run summary. It
binds the parent file SHA-256, copied tensor SHA-256, trainer source, optimizer,
scheduler, budget, objective, deployment buffers, and validation schedule. It
retains ordered trajectory IDs, sampled cores, buffer choices, and losses for
the first 16 updates. The ordered SHA-256 chain covers the update number and
trajectory/core selections for every committed update. The last update and
data, core, buffer, and model RNG states remain available in the P4 checkpoint.
Resume restores that checkpoint before another draw and preserves the audit.

The audit records selected raw detector columns per global and core query,
including available columns with zero event bits. It also records committed
step wall time, process CPU seconds, allocated CPU-core hours, and Linux
process peak RSS. Time and core-hours cover committed training steps through
feature construction and optimization and exclude setup, checkpoint I/O, and
validation. Peak RSS is a process high-water mark and can include earlier
children in a serial sweep. The token counts and timings describe different
observation loads under a matched update budget.

`training.validation_data_id` optionally adds a shared terminal-only diagnostic
on a finalized validation split. It records the validation dataset digest,
phase-local update, shot count, failures, and window LER. The terminal update
selects the checkpoint. If validation is interrupted, resuming the terminal
optimization checkpoint retries the diagnostic with the saved model state.
For matched comparisons, `analysis=adaptation` requests S+−W and W−D from
P5 prediction manifests. It checks the common parent, initial model, training
controls, trajectory/core chain, and deployment queries. P5 can still evaluate
an earlier checkpoint with saved training provenance. Matched contrasts
require the new audit evidence. [P5 verification](P5.md)

## Executed checks

| Test file | Independent expectation and observed behavior |
|---|---|
| `test_p6_continuation_fork.py` | An independent named-tensor inventory checks every copied parameter and a test normalization buffer. Parent Adam moments and scheduler counters are advanced. Forks reset both and use the prescribed initial learning rate. A changed head/buffer is detected without changing siblings or the parent. Carrying old moments or a scheduler into a fork is rejected. |
| `test_p6_continuation_streams.py` | Independent canonical seed and PCG64 calculations match three arms across chunk boundaries. Extra buffer draws leave the physical and core sequences intact. Replayed or skipped chunks, base-stream reuse, and an arm-derived seed fail the comparison. |
| `test_p6_dynamic_buffer_sampling.py` | Controlled integer draws enumerate all nine $\{0,3,5\}^2$ pairs. The independent P2 schedule checks all selected detector columns and the penultimate readout exclusion. All microbatches from one effective batch receive the same draw. |
| `test_p6_continuation_objective.py` | Literal float64 logits and scalar BCE verify equal global/core weighting and the mean over all 12 core choices. Real prepared features retain full global queries, target identities, and the zero-event row. Forcing D to the W buffers gives equal feature arrays, losses, model gradients, Adam and scheduler state, and updated parameters. |
| `test_p6_continuation_budget.py` | A parent at update seven plus three new updates ends at cumulative ten, consumes nine trajectories and 18 queries, and resumes only after its saved progress. Invalid budget, conflicting checkpoint operations, wrong global context, and unmatched sweep settings are rejected. |
| `test_p6_d5_matched_continuation.py` | Installed Hydra sweep runs all arms at $d=5,T=60,p=0.003$ from one real three-update checkpoint. Each arm performs two new Adam updates with $B=2$ and microbatch size one, retains true-label parity, and writes a common starting hash and input chain. The P2 schedule independently predicts detector-token counts. Terminal validation, S+/W/D and G/F companion inference, and P5 paired contrasts execute on the recorded splits. A changed input identity fails the contrast. |
| `test_p6_continuation_resume.py` | The installed CLI in a fresh process resumes D after one of three declared updates. Independent PCG64 integer draws match the saved buffer trace and next RNG state. The test also verifies readback at the completed budget and injects a terminal validation failure, which is retried without another optimizer update. |

The scalar BCE oracle uses absolute tolerance $10^{-14}$. The forced W/D
equivalence and fresh-process D replay use zero relative and absolute tolerance
for tensors and exact comparisons for losses, choices, IDs, state, and counts.
Resource measurements are inspected as recorded observations. Exact replay is
conditioned on the fixed CPU environment and unchanged operation sequence.
[PyTorch reproducibility](https://docs.pytorch.org/docs/2.7/notes/randomness.html)

## Environment and commands

The P6 source was based on `a87110f2ed5680803e630b5fdaafa877dd87081b`.
The independent run covered 95 Python and YAML source and test files with
combined SHA-256 `345d79a9858d7c1307061f3dbf0227763b73daa26f734b1872e52cd255a9420e`.
The fingerprint hashes each sorted relative path, a NUL separator, and its
binary SHA-256 digest.
Local tests used `nn_window_decoding` on Linux WSL2 x86-64 on an Intel Core
i7-13700H. The environment used Python 3.11.18, PyTorch 2.7.0+cpu, PyG 2.6.1,
NumPy 2.2.6, Stim 1.15.0, SciPy 1.17.1, Hydra 1.3.2, pytest 8.4.2, and
pytest-xdist 3.8.0. Ordinary workers were bound to CPUs 0–7. The workflow
fixtures use `runtime=test_cpu`, one Torch intra-op and inter-op thread per
worker, zero loader workers, inline sampling, and deterministic training.
The fresh-process test starts a synchronous child from its idle worker.

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export BLIS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 PYTHONHASHSEED=0
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  tests/unit/test_p6_*.py tests/integration/test_p6_*.py
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  -m 'not performance and not cluster' tests
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python exports/verification/P6/independent_probe.py
```

The focused run passed 11 tests. The independent cumulative run passed all
204 tests, including 193 inherited tests, with zero failures and skips. The
suite reported the 104 third-party Matplotlib/Pyparsing deprecation warnings
already observed in P5.

The independent probe exercised all three arms from a genuine distance-5 parent,
using $U_0=3$, $U_1=2$, $B=2$, and microbatch size one. Independently derived
trajectory, core, and buffer draws and detector-token counts matched the
records. The probe checked exact D replay in a fresh process, terminal
validation, and paired counts from the archived deployment decisions. It
rejected a multirun with unmatched learning rates and a separately trained W
with a different learning rate during P5 analysis. The ignored local probe
at the path above has SHA-256
`6b8e4881161f70b6a95ab14b579c08c5b2954c45e56823f07120d7b94ada2936`.
