# P1 verification

## Claim and configuration domain

C1 covers the Stim 1.15.0 rotated surface-code Z-memory circuit with fixed
cores of length $c=d$. The [local C0 evidence](P0.md) establishes the typed
configuration consumed by the pilot integration test. P1 passes the distance,
number of rounds, core length, and circuit probability to the simulator as
explicit parameters.

The physical circuit retains the generator's repeat blocks and global
observable. All four generator probabilities use the same $p$. Metadata uses
zero-based indices in the flattened physical circuit. Each cut is a gap
immediately after the round's complete ancilla MR, and each core interval
includes its start and excludes its end. The final core extends through
destructive data readout. Removing the teacher's internal Pauli annotations
recovers the flattened physical circuit exactly. The original global-only DEM
has one observable.

The latest contributing measurement determines detector availability. An
arrival has a one-based round number and a phase that orders the final
ancilla measurements before destructive readout. The detector coordinates
retain their Stim convention independently of this arrival ordering.

## Independent checks and finite coverage

The reference schedule specifies the physical logical support, MR and readout
instruction indices, ancilla order, and measurement dependencies for the
opening, bulk, and closing detectors. The frame oracle consumes the physical
Clifford instructions and these reviewed constants. It derives each core's
expected logical contribution from the final parity of faults in that
interval. It checks the cumulative signs separately and uses no production
cut, parity, or availability logic.

## Algebraic argument and limits

The oracle represents a relative Pauli frame by binary X and Z components.
Conjugation by H, S, and CX acts linearly on those components. Intended
Pauli gates can change the phase but leave the components unchanged. A Z
measurement reads the X component plus any separate record flip. After a
non-reset Z measurement, the oracle discards Z as a phase on the measured
eigenstate and retains X as the relative eigenstate flip. MR reads the record
before clearing both components. The generated circuit uses pre-measurement
X-error channels, and the explicit MR(1) tests additionally exercise the
pure record-flip interpretation.

Backward propagation of the literal physical logical representative through
each ideal round reproduced the same data support with no ancilla factors in
both fixtures. In this static CSS schedule, a Z check preserves data Z through
its data-to-ancilla CNOTs. Each X check has even overlap with the chosen
logical support, so the ancilla factors cancel. Measurement projections and
ancilla resets at the completed round preserve that representative. Newly
introduced stabilizer-frame factors commute with it at the clean cuts. A
partial extraction round lacks that guarantee.

Induction through the binary rules gives linear detector and parity effects
for fixed, physically realizable fault patterns. When the complete rounds
preserve the representative, differences of successive signs isolate the
interval contributions. The reference starts before noisy preparation with
$G_0=0$ and ends with the actual final parity $G_J=Y$. This also explains why
XOR agreement alone cannot validate ownership. Full elementary coverage is
for the distance-3 fixture. The distance-5 checks are selected cases.
The stochastic channel probabilities and the joint sampler depend on the
pinned Stim implementation. The tests do not measure a decoder error rate
or establish compatibility with an allocated compute node.
[Stim observable semantics](https://github.com/quantumlib/Stim/blob/v1.15.0/doc/gates.md#the-observable_include-instruction)

## Executed commands and results

The source was the P1 working tree based on `041d60d`. Verification used the
`nn_window_decoding` Conda environment on Linux x86-64 under WSL2 with
Python 3.11.18, Stim 1.15.0, NumPy 2.2.6, PyTorch 2.7.0+cpu, pytest 8.4.2,
and pytest-xdist 3.8.0. CPU affinity was 0–7, and each of the eight test
workers used one numerical thread.

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export BLIS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 PYTHONHASHSEED=0
export PYTEST_DEBUG_TEMPROOT="$(mktemp -d /tmp/nnwa-p1-phase.XXXXXXXX)"
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  tests/unit/test_p1_*.py tests/integration/test_p1_*.py
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  -m 'not performance and not cluster' tests
```

## P2 handoff

```bash
conda run --no-capture-output -n nn_window_decoding python - <<'PY'
from nn_window_ablation.simulation import CircuitSpec, build_circuit_bundle, sample_shots

bundle = build_circuit_bundle(CircuitSpec(5, 60, 5, 0.003))
shots = sample_shots(bundle, 10, seed=0)
print(shots.detectors.shape, shots.core_labels.shape)
```

Use `CircuitBundle.detectors` for the measurement-derived arrival and
coordinates, and use `ShotBatch.detectors` for the physical detector bits.
Keep the label arrays separate from graph inputs. P2 must independently
verify that its window selection respects detector availability, including
the distinction between final-round ancilla arrivals and destructive
readout. P4 owns persistent dataset and shard identities. `sample_shots`
currently assigns consecutive caller-offset IDs within each batch.
