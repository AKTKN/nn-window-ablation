# P7 verification

## Claim and scope

C7 covers local PBS planning, evidence of workflow completion, verified archive
transfer, and portable reconstruction of paired statistics. It depends on
C4 dataset and checkpoint integrity, C5 paired outputs and analysis, and C6
matched continuation provenance. The local tests use bounded fixtures and a
simulated PBS transport. Allocated-node acceptance is a separate gate.
[P4](P4.md) · [P5](P5.md) · [P6](P6.md)

## PBS plan and run receipts

`nnwa pbs render --spec job.json --output job.pbs` resolves the workflow and
checks budgets before writing a script. A plan specifies the stage, portable
job and run names, full source revision, absolute checkout and Conda paths,
data/run roots, a unique receipt directory, requested resources, and explicit
threads. Generation, profiling, training, resume, evaluation, and the import
probe use the same runner. Queue and account are optional.

The script calls the selected Conda executable with
`run --no-capture-output -p PREFIX`. The compute runner compares the clean Git
checkout and installed package bytes to the plan, checks the actual prefix and
path visibility, and checks the CPU budget against process affinity and
`PBS_NCPUS` when available. It records the requested resources, observed CPU
affinity, scheduler identity, nodefile slot counts, resolved thread settings,
and measured workflow thread counts when available. Nodefile slots and CPU
affinity describe different observations. The runner writes the command's
output to `stdout.log` and atomically updates `job.json`.

Job receipt schema 1 has planned, running, complete, failed, and incomplete
states. A terminal complete receipt requires successful command exit and
stage-specific artifact verification. An interrupted job can leave a running
receipt with no terminal proof. `nnwa pbs status` separately queries OpenPBS
and checks the selected receipt's job ID and artifact digest before reporting
completion. Rendering invokes no scheduler or transfer commands.
[OpenPBS qsub](https://github.com/openpbs/openpbs/blob/master/doc/man1/qsub.1B) ·
[OpenPBS qstat](https://github.com/openpbs/openpbs/blob/master/doc/man1/qstat.1B) ·
[Conda run](https://docs.conda.io/projects/conda/en/stable/commands/run.html)

## Portable bundles

`nnwa export --dataset PATH --report PATH --output RESULTS.tar.gz` verifies the
original P4 dataset and P5 prediction manifests, including physical query
metadata, before recomputing the reported statistics. It checks the saved
CSV tables and retains the selected report, prediction inventories, original
dataset and shard manifests, packed labels, and shot IDs. It preserves run
and checkpoint identities, inference and training provenance, and available
completed training receipts. Use `--log PATH` for scheduler receipts, logs,
and environment inventories. All active paths in the top-level manifest are
relative to the extracted root. Historical paths inside copied metadata
remain provenance.

| Capability | Required archived content |
|---|---|
| Statistics | Global and core labels, trajectory IDs, packed decisions and logits, resolved policy and analysis seed, reports, and checksummed provenance. |
| Re-decoding | Statistics content plus `--include-detectors` and `--include-checkpoints`, which retain the physical circuit and structure, raw detector shards, and the selected terminal checkpoint bytes. |
| Optional stored training inputs | One or more selected finalized train datasets supplied with `--training-dataset PATH`. |

Included terminal checkpoints can initialize eligible new continuations.
Exact same-run resume follows the P4/P6 original-path, source, and runtime
contract. [Resume contract](P4.md#interfaces-and-schemas)

Bundle schema 1 lists each relative member with its size and SHA-256. The
writer verifies the staged content and scans the complete compressed archive
before publishing it as a new file. The extractor accepts a gzip-compressed tar
with its manifest first and an exact inventory of regular members. It rejects
duplicates, absolute and noncanonical paths, traversal, links, extra or missing
members, changed bytes, and truncated gzip data. Extraction stages in a new
directory and checks hashes before publication. The writer leaves source
artifacts in place. [Python tarfile](https://docs.python.org/3.11/library/tarfile.html)

`nnwa reanalyze --bundle DIRECTORY --output NEW_DIRECTORY` verifies the bundle,
maps its packed label and prediction rows, and runs the same P5 statistics
kernel with the stored interval method, sparse cutoff, contrast order, and
PCG64 settings. It requires the recorded NumPy and SciPy versions, checks the
reconstructed report and tables, and writes results to a separate directory.
Statistics-only replay opens no detectors or circuit files and requires no
checkpoint. Integrity verification of a full bundle reads the bytes of its
included optional files. The integrated fixture exercises statistics-only
replay using an installed fresh CLI process with the original paths removed.
Re-decoding is checked separately.

## Executed checks

| Test file | Expectation and observed behavior |
|---|---|
| `test_p7_pbs_rendering.py` | Literal directive and argv expectations verify spaces, optional queue/account, portable names, all six stages, and missing budgets or excess CPUs/workers. Bash syntax passes and the sentinel qsub, ssh, and scp binaries are unused. |
| `test_p7_job_status.py` | The injected transport checks qstat arguments, planned/running states, nonzero or absent exit evidence, and rejection of absent or changed output receipts. It establishes local status behavior. |
| `test_p7_export_manifest.py` | Stdlib tar/JSON and NumPy readers check exact file contents and independently recomputed SHA-256 values. Missing labels, changed or truncated bytes, reordered IDs, schema mismatches, and unfinished runs are rejected. |
| `test_p7_archive_portability.py` | A fresh destination with a different name receives the exact declared members. Truncated gzip, duplicate members, absolute and noncanonical paths, traversal, symlinks, and hardlinks fail without publishing or altering source files. |
| `test_p7_export_statistics.py` | Literal failure tables and independent Wilson, beta-quantile, and paired-bootstrap calculations check both interval branches and signed differences. Analysis succeeds with no checkpoint. Missing labels, modified predictions, and a relabeled checkpoint condition fail. |
| `test_p7_d5_export_reanalysis.py` | Genuine 60-round, distance-5 Stim shots at $p=0.003$ pass through the 256-wide four-layer GRU and G/F/S evaluation. The clean-room process reconstructs exact report values and CSV bytes with detector/circuit/model access guarded. A separate full export restores the canonical model state and re-decodes a subset. The P6 fixture also exercises archived S+/W/D provenance and contrasts. |

Saved predictions, shot IDs, model state hashes, counts, and replayed tables
use exact comparisons. Re-decoded float32 logits use absolute tolerance
$2\times10^{-6}$ and relative tolerance $10^{-5}$ for possible batching-order
differences. Independent interval oracles use float64 comparisons.

## Environment and commands

The P7 source was based on `03cc68ac7d3e68cc47af363c4c94fab550ea12b7`.
The independently tested 106 Python and YAML files under `src` and `tests`
had combined SHA-256 `fa0c7d1173aa94dd4acfafd788990efa23e32cd5fcd42f103c5df61d1686ea64`.
The fingerprint hashes each sorted relative path, a NUL separator, and its
binary SHA-256 digest.
Local execution used `nn_window_decoding` on Linux WSL2 x86-64, Intel Core
i7-13700H, Python 3.11.18, PyTorch 2.7.0+cpu, PyG 2.6.1, NumPy 2.2.6,
SciPy 1.17.1, Stim 1.15.0, PyMatching 2.2.2, Hydra 1.3.2, pytest 8.4.2,
and pytest-xdist 3.8.0. The ordinary workers were bound to CPUs 0–7 with
one numerical thread each. Scientific child commands use `runtime=test_cpu`,
zero data-loader workers, and inline sampling.

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export BLIS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 PYTHONHASHSEED=0
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  tests/unit/test_p7_*.py tests/integration/test_p7_*.py
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  -m 'not performance and not cluster' tests
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python exports/verification/P7/independent_probe.py
```

The focused run passed 36 tests in 37.09 seconds. The final independent
cumulative run passed all 240 ordinary tests, including 204 inherited cases,
in 67.53 seconds. Both runs had zero failures and skips. The cumulative run
reported the 104 third-party Matplotlib/Pyparsing deprecation warnings already
seen in P5 and P6.

The independent probe passed in approximately 45 seconds. It checked offline
rendering and injected qstat responses, then ran a rendered one-shot generation
job through Conda from a temporary fixed Git checkout with simulated PBS
metadata. It independently verified archive members, Wilson and exact interval
bounds, and rejection of truncated or unsafe archives. The probe also guarded
physical and model access during statistics-only replay and re-decoded a row
from the relocated full bundle. The ignored local probe at the path above has
SHA-256 `5c14c18c968e693abc7f9121fafe434575498706e3c85155868c1b86635f6b6d`.

The [getting-started walkthrough](../GETTING_STARTED.md) ran verbatim after
installation using the existing environment. Both replayed CSVs matched their
archived originals byte for byte. The cluster guide's planning block rendered
all six job scripts with scratch paths. The rendered scripts, retained PBS
examples, and guide Bash blocks passed `bash -n`.

## Allocated-node acceptance pending

The available workspace had no `qsub` or `qstat` executable and no authorized
cluster destination was established. Use the site-approved procedure in the
[PBS cluster guide](../04_cluster_workflow.md) to record each gate.

- Import the pinned CPU dependencies in a small allocated job and verify checkout,
  Conda, and data/run path visibility from that node.
- Submit the rendered generation, training, and evaluation scripts from the
  fixed checkout. Compare requested resources with observed CPU affinity and
  scheduler accounting. Retain the receipts and logs.
- Pause and resume a bounded training run on the allocated machine and check
  the terminal update count and checkpoint hash.
- Transfer a completed bundle and its checksum from the cluster. Verify both the
  transfer checksum and extracted inventory, then replay its statistics locally.

The local fixture results establish workflow composition. Production budgets,
cluster performance, and decoder accuracy remain open.
