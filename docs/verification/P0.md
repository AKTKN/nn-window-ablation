# P0 verification

## Claim and scope

C0 is established for local configuration validation with the installed
Python 3.11 package, built-in Hydra presets, and Hydra's basic launcher.
Code, noise, window, model, and runtime values reach the typed resolver with
the documented override precedence. Invalid settings and unresolved execution
requirements are rejected. The validation workflow associates a resolved record
with each unique run and sweep child.

The claim relies on Hydra 1.3.2 composition, OmegaConf 2.3.0 structured
conversion, the declared CPU concurrency model, and PyTorch 2.7.0+cpu thread
semantics. The CPU calculation assumes one CPU for each loader and parallel
sampler worker. A sampler with `sampling_processes=1` runs inline. Each
application process is charged intra-op times inter-op threads in addition to
workers. The test launcher used at most eight numerical CPUs.

## Environment and source

The P0 working tree based on `ed48a60` was tested on Linux x86-64 under WSL2
with an Intel Core i7-13700H. The Conda environment used Python 3.11.18,
pytest 8.4.2, pytest-xdist 3.8.0, and PyTorch 2.7.0+cpu from the official CPU
wheel index. The complete local Conda builds and pip versions are recorded in
the [Conda inventory](../../environments/local-linux-64.conda.txt) and
[pip inventory](../../environments/local-linux-64.pip.txt).

`conda create --file` recreated the pinned base in a temporary prefix, and the
recorded CPU wheel and pip pins were installed there. A wheel built with
`python -m pip wheel --no-deps --no-build-isolation` was installed with
`python -m pip install --no-deps <wheel>`. `pip check` passed. The project and
all declared dependencies imported from the fresh prefix. PyTorch reported
`torch.version.cuda is None`. With no inherited `PYTHONPATH`, the wheel's
`nnwa validate` wrote a configuration record from outside the checkout.

The cumulative pytest suite ran from the editable Conda installation. Its
integration fixture built a wheel once and installed it into a temporary
virtual environment using the recorded Conda dependencies. The subprocess
check located the package in the wheel installation. The CLI loaded
`nn_window_ablation/conf/config.yaml` and its groups through the installed
package-data path.

## Executed tests

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export BLIS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 PYTHONHASHSEED=0
taskset -c 0-7 conda run --no-capture-output -n nn-window-ablation \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  -m 'not performance and not cluster' \
  tests/unit/test_p0_config.py tests/unit/test_p0_runtime.py tests/unit/test_p0_paths.py \
  tests/integration/test_p0_installed_cli.py
taskset -c 0-7 conda run --no-capture-output -n nn-window-ablation \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  -m 'not performance and not cluster' tests
```

| Run | Passed | Failed | Skipped | Wall time |
|---|---:|---:|---:|---:|
| P0 focused | 61 | 0 | 0 | 10.52 s |
| Local cumulative | 65 | 0 | 0 | 9.31 s |

Each session ran with affinity restricted to CPUs 0–7 and one native,
PyTorch intra-op, and PyTorch inter-op thread per worker. CLI subprocesses
used `runtime=test_cpu runtime.processes=1 data.num_workers=0 data.sampling_processes=1`.
The initial focused run revealed that the test fixture put a Hydra flag after
the overrides. The corrected fixture puts flags first and passed the targeted
wheel rerun and both final runs.

## P1 handoff and pending checks

`config.resolve_config` exposes typed `code`, `noise`, and `window` settings,
`geometry` with the integer round and core lengths, and `seed`. P1 can pass
these values to the simulator as explicit inputs, with
`noise.circuit_probabilities` available for the four Stim generator parameters.
For a local configuration check, run `nnwa validate runtime=local_cpu`.

The C0 result covers local installation, configuration, and startup controls.
Allocated compute-node compatibility remains pending. P1 establishes circuit
and label correctness, including the independent Pauli-frame oracle and
shotwise XOR ownership checks.
