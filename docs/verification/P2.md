# P2 verification

## Claim and prerequisites

C2 establishes the observation contract for the P1 rotated-Z memory circuit.
Each feature record depends on the selected physical detector bits, public
circuit geometry, observation schedule, and target interval. The local C1
evidence supplies the physical record IDs, measurement dependencies, core
partition, and arrival phases. [P1 verification](P1.md)

`build_observation_layout` derives a detector's layer from its declaration
position relative to the MR and destructive-readout instructions. It derives
availability separately from the latest required measurement. A detector whose
layer is retained keeps its original parity even if a prerequisite measurement
is earlier than the left edge of the window.

`select_window` uses the same `TargetQuery` for restricted and full-context
core inference. The core index is zero-based, and the target's first and last
extraction rounds are inclusive. A global query has a null core index and
spans the physical trajectory. Expected inputs are full-phase observations
for a global or full-context core query and the specified buffers for a
restricted core query. The supported buffer lengths are $0$, $\lceil d/2\rceil$,
and $d$. At $d=5$ they are 0, 3, and 5 rounds. The default core 11 deadline is
$T^{-}$, and core 12 includes the actual readout layer at $T^{+}$ even with a
zero right buffer.

## Graph and batch conventions

- Slots use physical layer indices 0 through $T-1$ for ancilla rounds 1 through
  $T$ and layer $T$ for destructive readout at round $T$. Unavailable guards
  mark adjacent excluded physical context. Padding marks positions outside the
  circuit, including any requested buffer beyond its edges. Preparation and
  readout flags follow observed physical layers.
- Cropping copies only permitted detector columns. Consecutive observed layers
  form overlapping two-layer graph groups. An isolated observed layer forms
  one group with its following unavailable or padding slot. A group never
  spans a missing physical layer. Every group retains a graph for each tile,
  including graphs with zero events. A full $T+1$-layer history has $T$ groups.
- Spatial coordinates use the pinned Lange convention. Coordinates shift to
  the origin of the public patch, convert to integer coordinates in Stim
  units, and shift to each tile's local origin. Tiles follow the upstream
  stabilizer-position filter and y-then-x order, with outer tiles first for
  nested grids. Node times are 0 or 1 within a group. Distinct nodes have both
  directed edges, with weight equal to inverse squared Chebyshev distance and
  zero weight at zero distance. Graphs carry the physical detector index for
  each node. [Pinned Lange graph source](https://github.com/LangeMoritz/modular-gnn-rnn-decoder/blob/458210ac74ed0047760b8789c169e6b9eff732b8/gnnrnn/graphs.py)
- Packed detector rows use little-endian bit order with a valid detector
  count and aligned shot IDs. Batched graphs use prefix offsets for examples,
  nodes, and edges. Repeated offsets preserve empty graphs through unbatching.
  The explicit model-array export contains geometry and identity arrays.
  Shot IDs are join keys. Supervision joins by shot ID and target core in a
  separate output, with the global label selected only for the global query.

The [upstream record](../../third_party/README.md) identifies the adapted
conventions and retained notice. The built wheel was inspected and contains
the original MIT license bytes.

All detector IDs, mask membership, graph coordinates, graph edge arrays, and
test labels were checked with exact comparisons. C2's dependency claim also
follows from the interface: two histories that agree after raw cropping give
the same bit array to the graph constructor and the same fixed metadata.
The fixtures check that the production pipeline realizes this condition.

## Execution and independent review

The tested P2 working tree was based on `a1fbbb8`. Both runs used
`nn_window_decoding` on Linux x86-64, Python 3.11.18, Stim 1.15.0,
NumPy 2.2.6, PyTorch 2.7.0+cpu, pytest 8.4.2, and pytest-xdist 3.8.0.
Each run used eight workers with CPU affinity 0–7 and one numerical thread
per worker.

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export BLIS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 PYTHONHASHSEED=0
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  tests/unit/test_p2_*.py tests/integration/test_p2_*.py
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  -m 'not performance and not cluster' tests
```

| Run | Passed | Failed | Skipped | Wall time |
|---|---:|---:|---:|---:|
| Focused P2 | 23 | 0 | 0 | 13.35 s |
| Independent cumulative run, including 88 inherited checks | 111 | 0 | 0 | 19.83 s |

The independent reviewer also compared the installed P2 implementation
against the exact pinned upstream source. Across $d=3,5,7,9$, 1,380 full-context
graph slots and 106,356 directed edges matched exactly, including tile order,
node identities, coordinates, and weights. The reviewer independently checked
all 108 pilot masks and their invariance to changes in excluded bits. The review
also confirmed correct exclusion at $T^{-}$ with misleading geometric time and
stale detector-level phase metadata. The review found a missing type check on
manually constructed supervision IDs, which was corrected and covered by a test
before the independent cumulative run.

The standalone review probe and its pinned upstream input are archived locally
in `exports/verification/P2/`. With the thread exports above, the retained
probe can be rerun as follows.


## P3 handoff

Build a public layout with `build_observation_layout` and reuse
`build_feature_geometry` for queries on that layout. Pass the result of
`select_window` and `crop_observations` to `build_features`.

```bash
conda run --no-capture-output -n nn_window_decoding python - <<'PY'
from nn_window_ablation.features import batch_features, build_feature_geometry, build_features
from nn_window_ablation.simulation import CircuitSpec, build_circuit_bundle, sample_shots
from nn_window_ablation.windows import Buffers, build_observation_layout, crop_observations, select_window

bundle = build_circuit_bundle(CircuitSpec(5, 60, 5, 0.003))
shots = sample_shots(bundle, 2, seed=101)
layout = build_observation_layout(bundle)
view = select_window(layout, layout.core_query(10), Buffers(5, 5))
cropped = crop_observations(view, shots.detectors, shots.shot_ids)
batch = batch_features(build_features(cropped, build_feature_geometry(layout)))
print(view.metadata.release, batch.example_graph_offsets.tolist())
PY
```

`FeatureBatch.examples` gives each target, its group and tile order,
observation masks, and boundary flags. P3 will use these fields alongside
graph arrays and learned embeddings for empty graphs. P3 must verify state
reset and the absence of learned cross-query caches before drawing
prediction-level conclusions. This record establishes C2 for the stated
layouts and observations. Model accuracy and allocated compute-node
validation remain pending.
