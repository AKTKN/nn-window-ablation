# P4 verification

## Claim and prerequisites

C4 covers trajectory identity, persistent datasets, fixed-update training, and
exact checkpoint replay in the recorded CPU environment. P0 established the
installed configuration and runtime setup. P1 established the physical
detectors and clean-cut labels. P2 established observation availability and
feature isolation. P3 established the shared model and normalized objective.

## Interfaces and schemas

- `nnwa generate` writes a finite train, validation, or test dataset.
  `data.open_dataset(path, expected_split=...)` verifies the final manifest,
  reconstructs the physical bundle, and opens read-only shards. Each shard's
  `.read(rows)` unpacks selected complete trajectories and returns their IDs
  and separate detector, global-label, and core-label arrays. The persisted
  physical artifacts are the original circuit, teacher circuit, original
  global DEM, and metadata for detector arrivals, clean cuts, and observables.
- Dataset schema 1 records the physical, feature, and label provenance,
  array shapes and valid bits, and SHA-256 and byte lengths for its inventory.
  It stores three little-endian packed `uint8` arrays and one `int64` array of
  join keys. The authoritative trajectory ID is the full dataset recipe
  digest, shard index, and row index. Numeric join keys encode the split and
  phase, a truncated recipe digest, and the absolute row. Use full IDs for
  joins across datasets. Zero-event rows keep their original IDs.
- Seed recipe 1 derives unsigned 64-bit role seeds from canonical JSON and
  SHA-256. It uses the master seed, family, split, distance, replicate, and
  phase. A per-chunk ordinal selects each Stim sampling call and PCG64 row
  permutation. The recipe records the Stim version, call policy, chunk size,
  and any finite total. Initialization, sampled core, dynamic buffer, Torch,
  and Python stochastic operations have separate roles. The three continuation
  arms share one namespace distinct from base training. Dynamic buffers draw
  one pair per effective batch and reuse it in its microbatches.
- `nnwa train` takes generated chunks or a finalized train dataset and stops
  at the declared phase-local update budget. It weights each microbatch mean
  by its fraction of the effective batch, then steps the optimizer and any
  scheduler once. Per-phase trajectory and query-example counts are $UB$ and
  $2UB$. The parent counter is recorded separately from phase and cumulative
  updates. The workflow supports explicit SGD or Adam and a disabled or step
  scheduler. Phase presets leave scientific run budgets unresolved.
- Checkpoint schema 1 uses a single ZIP envelope with a JSON integrity record
  and a CPU PyTorch state payload. It records model weights and buffers,
  optimizer, optional scheduler, counters, cursor, the last completed update,
  NumPy bit-generator states, Torch CPU RNG, and Python RNG. Workflow
  checkpoints also record the resolved configuration, package source digest,
  source revision, environment, and parent artifact if applicable. Initializing
  a continuation copies the terminal base model into fresh optimizer, scheduler,
  and continuation streams. Resume reconstructs and restores the original run
  before consuming another batch. Evaluation loads the model in inference mode
  at the fixed terminal update via `checkpoints.load_evaluation_model`.

Artifacts use staged writes, file and directory `fsync`, and same-filesystem
rename on Linux. The platform filesystem must supply atomic rename, sync, and
advisory file-lock semantics. Readers consume completed dataset manifests and
integrity-checked envelopes. The exclusive run lock allows one active updater
per run directory. Before checkpoint replacement, an interruption leaves the
previous completed checkpoint usable. Once a new checkpoint is published, its
counter is authoritative and can repair an absent or stale `run.json`.

Checksums verify that bytes agree with the recorded inventory. The independent
fault fixture checks the separate scientific assertion that label rows belong to
the trajectories they accompany. Stored test arrays are the portable input for
paired evaluation. Exact regeneration and replay rely on the recorded package
versions, compatible CPU/platform, and identical operation and sampling-call
sequences. [NumPy packing](https://numpy.org/doc/stable/reference/generated/numpy.packbits.html) ·
[NumPy memory mapping](https://numpy.org/doc/stable/reference/generated/numpy.load.html) ·
[Stim sampling](https://github.com/quantumlib/Stim/wiki/Stim-v1.15-Python-API-Reference) ·
[PyTorch reproducibility](https://docs.pytorch.org/docs/2.7/notes/randomness.html)

## Executed checks

| Test file | Expectation and observed behavior |
|---|---|
| `test_p4_shards_and_identity.py` | Literal bytes and an independent NumPy unpack verify little-endian encoding and padding. Full and numeric IDs remain stable in reverse reads and disjoint across splits. Byte changes, truncation, wrong shapes, duplicate IDs, role reassignment, swapped label files, and invalid padding fail. An independent P1 Pauli-frame fixture detects a core-label row swap that preserves both checksums and shotwise XOR in a newly sealed dataset. |
| `test_p4_rng_namespaces.py` | An independent seed calculation and Stim samples agree when assigned chunks are requested out of order. Independently seeded PCG64 reproduces the physical ordering and core indices after cursor/RNG reconstruction. Reused shards give the same arrays and IDs as on-demand sampling with the same finite recipe. Deliberate reuse of the base namespace and use of an arm-dependent seed produce different traces. Extra buffer draws preserve trajectory and core sequences. A failed chunk read leaves the original cursor available for retry. Frozen artifacts open after a simulated Stim version change and attempts to regenerate them fail. |
| `test_p4_trainer_update_oracle.py` | The analytic scalar SGD recurrence with targets 1, 4, and 9 agrees with both whole-batch and uneven 2+1 microbatch updates and rejects double normalization. The test-only dropout objective replays exactly after restoring RNG and uses one buffer pair per effective batch. Replacing either restored Torch or Python RNG with its initial state changes the resumed loss. |
| `test_p4_checkpoint_failures.py` | A failure before atomic replacement preserves the previous checkpoint byte for byte. The loader rejects incomplete envelopes, a newer schema, altered state bytes, and incompatible update budgets or optimizers. A failure during final dataset publication leaves the target unavailable, and a completed retry opens. Seven base updates plus four new continuation updates end at local update 4 and cumulative update 11. Fork resets the optimizer and scheduler, and resume restores their updated states. |
| `test_p4_paired_data_pipeline.py` | Genuine distance-5, 60-round noisy and zero-noise trajectories survive persistence with the same arrays, identities, and XOR parity. P2 full/global and buffered final-core queries give exact P3 logit equality before and after storage. Reordering the persisted ID payload fails verification. A workflow trained from stored train shards resumes from its initial checkpoint, binds the dataset manifest digest, and leaves a terminal checkpoint byte-identical when reopened. |
| `test_p4_d5_train_resume.py` | The full width-256, four-layer GRU with dropout zero replays four Adam updates in a 2+2 interruption test against a four-update control. Both declare four updates at the start. Trajectory IDs, selected cores, losses, model weights and buffers, Adam moments, StepLR state, counters, RNGs, cursor, and next-stream reads agree exactly. An inconsistent cursor fails restoration and zeroed Adam moments change the final weights. The evaluation loader requires the terminal checkpoint and exactly restores its model. |

For the analytic scalar recurrence the absolute and relative float64 tolerances
were $10^{-15}$. The composed distance-5 replay used exact equality for its
float32 tensors and losses. Its bounded settings were $B=2$, one trajectory per
accumulation microbatch, three rows per sampling chunk, Adam with learning
rate `0.001` and `foreach=False`, and StepLR with step size 1 and gamma `0.9`.

## Environment and commands

The working tree was based on `c8658235fa4f7fbf9363b4342261b0cb9c716408`.
The independently tested Python and YAML source and test files had combined
SHA-256 `4d716cbcbcbef32c30ea3ba83d73b1998af3dfb8976a49c634c3cd7ee4dc7ede`.
The fingerprint hashes each sorted relative path, a NUL separator, and its
binary SHA-256 digest.
Local execution used `nn_window_decoding` on Linux x86-64, Intel Core
i7-13700H, Python 3.11.18, PyTorch 2.7.0+cpu, PyTorch Geometric 2.6.1,
NumPy 2.2.6, Stim 1.15.0, Hydra 1.3.2, pytest 8.4.2, and pytest-xdist 3.8.0.
The ordinary suite used one numerical thread per worker. The P4 workflow
and full-model tests used `runtime=test_cpu`, with one Torch intra-op thread,
one inter-op thread, zero loader workers, inline sampling, and deterministic
Torch algorithms for training.

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export BLIS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 PYTHONHASHSEED=0
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  tests/unit/test_p4_*.py tests/integration/test_p4_*.py
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  -m 'not performance and not cluster' tests
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python exports/verification/P4/independent_probe.py
```

The final focused run passed 26 tests. The independent ordinary run passed 152
tests, including 126 inherited tests. Both had zero failures or skips.

The independent probe read genuine pilot rows
backwards from read-only mappings, checked parity, and rejected cross-split IDs
even after their file integrity records were recomputed. It injected failures at
the next chunk read, at cross-chunk array assembly, and at the final status
write. Retries reproduced the expected data and preserved the terminal
checkpoint byte for byte. Its local ignored copy at the path above has SHA-256
`3a46fc113f904f199a6bc0e0deb4546498329796792c03aa486c2e4c02ec1281`.

An installed-command smoke run in a scratch directory used the [README's
bounded generation and training commands](../../README.md#generate-data-and-train).
It verified a 2+1 shard split, terminal base-model reload, and byte-identical
terminal resume. Repeating the bounded training command with
`run_name=pilot-fork training=dynamic_window checkpoint.init_from=runs/pilot-check/checkpoint.pt`
produced one new update, cumulative update two, and a recorded buffer pair.
Replacing `checkpoint.init_from` with
`checkpoint.resume_from=runs/pilot-fork/checkpoint.pt` preserved that completed
checkpoint byte for byte.
