# P3 verification

## Claim and prerequisites

C3 covers the local CPU query model, shared objective, and prediction
isolation for the P2 input contract. The independent cumulative run
included 111 inherited checks. C0 supplies typed settings and startup
limits, C1 supplies physical trajectories and checked labels, and C2
supplies cropped graphs and label-independent metadata. [P0](P0.md) ·
[P1](P1.md) · [P2](P2.md)

`prepare_model_batch` converts the P2 arrays to graph tensors and checks
graph and tile order, node offsets, and edge membership. `ModelBatch`
carries graph tensors, valid sequence lengths, and 17 public metadata
values per group. Three values identify a global target and observed
preparation/readout boundaries for the query. Each of its two slots has
round distances from the target cuts, divided by $d$, a three-way
observation state, and observed preparation/readout flags. Shot IDs remain
join keys in the P2 records.

`QueryDecoder` uses weighted GraphConv 3→64→256, ReLU, mean pooling, the
learned empty vector, distance-specific tile aggregation, a width-256
four-layer GRU with dropout zero, and one shared scalar head. The
bias-free query projection is added before recurrence. The GRU starts
with its implicit zero state for each packed sequence. The head consumes
each sequence's last valid state. Model construction uses the normal
PyTorch and PyG initializers kept by upstream, with its zero-initialized
trainable empty vector. The new projection uses PyTorch's default linear
weight initializer. The pilot constructs all modules directly at $d=5$.

`query_loss` takes explicit logits and labels. With all core logits, it
averages the per-core BCE over $J$ and over trajectories. With one sampled
logit per trajectory, it gathers that trajectory's selected label from the
full core-label matrix. The default weights are one half each for the global
and core terms. `sample_core_indices` draws one uniform zero-based core
index per trajectory from a caller-owned NumPy stream. The mean of the
sampled estimator and its gradient over the finite core choices equals the
full objective. `hard_decisions` uses logit zero as the inclusive threshold.
[PyTorch BCEWithLogitsLoss](https://docs.pytorch.org/docs/2.7/generated/torch.nn.BCEWithLogitsLoss.html)

The model payload records the architecture, ordered metadata fields, schema
version, and strict state dictionary. The loader preserves the caller's CPU
RNG state and rejects incompatible metadata. P4 owns optimizer, data cursor,
and run-level checkpoint state. The exact upstream reference files and
license are stored locally for offline differential tests.
[Source, hashes, license, and adaptations](../../third_party/README.md)

Analytic float64 comparisons used absolute and relative tolerances of
$10^{-12}$. Float32 component comparisons used absolute $10^{-7}$ and
relative $10^{-6}$ tolerances for reductions and recurrent arithmetic.
The spatial comparison used identical channels-last layouts and exact
equality. The first focused run exposed a $2.98\times10^{-7}$ difference
between float32 convolution memory layouts. Matching the layout gave zero
difference, and the two layouts agreed to $1.81\times10^{-16}$ in float64.
Mixed-length and reordered float32 comparisons used absolute $2\times10^{-6}$
and relative $10^{-5}$ tolerances for batching arithmetic. Unchanged
inputs, evaluation state, A→B→A, and checkpoint readback were checked
exactly.

## Commands and independent review

The tests used the P3 working tree based on `002074b` in
`nn_window_decoding` on Linux x86-64 with Python 3.11.18, PyTorch 2.7.0+cpu,
PyG 2.6.1, NumPy 2.2.6, Stim 1.15.0, Hydra 1.3.2, pytest 8.4.2, and
pytest-xdist 3.8.0. Processes were bound to CPUs 0–7. Ordinary workers each
used one numerical thread. The separate performance session ran one pytest
worker with synchronous, freshly started profiling children.

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export BLIS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 PYTHONHASHSEED=0
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
  python -m pytest -n 8 --dist=load --strict-markers --strict-config \
  tests/unit/test_p3_*.py tests/integration/test_p3_*.py
taskset -c 0-7 conda run --no-capture-output -n nn_window_decoding \
```

The independent probe compared the entire distance-5 backbone with the
unmodified pinned decoder using copied weights and neutral metadata.
Logits differed by at most `5.59e-9` on the matched input. It also checked
mixed-length and reordered queries, all 1,080 excluded penultimate columns,
immutable state and checkpoint reload, and float64 BCE/gradient and
sampled-core expectation calculations. The review prompted an adapter
check for corrupted graph-group and tile order, which was covered before
the final independent run. The one-thread profile smoke and PBS template
syntax passed independently.

## Bounded CPU profile

The workload used the full pilot ($d=5,T=60,W=15,p=0.003$) on a local
Intel Core i7-13700H under WSL2, with eight allowed CPUs. Each child used one
application process, one inter-op thread, zero loader workers, and one
inline sampler. Batch size was two complete trajectories, with one warm-up
and two measured iterations at each setting. The training cycle made one
global and one sampled full-context core query per trajectory. The
separate evaluation path made all 12 restricted core queries per
trajectory. Serialization measured the architecture and weight payload in
memory, at 7,792,777 bytes for each setting.

## P4 handoff

Build `QueryDecoder(distance)` for a fresh model or restore a compatible
model payload via `QueryDecoder.from_checkpoint`. P4 can prepare and join
examples in trajectory order using the P2 identities, call
`prepare_model_batch` for the model inputs, and pass logits and supervised
targets to `query_loss`. Use the caller-owned stream passed to
`sample_core_indices` to preserve trajectory/core identity through resume.
P4 still needs persistent dataset and optimizer checkpoint records and an
independent resume-equivalence test.
